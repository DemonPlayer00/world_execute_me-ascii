# world.execute(me); — TTY 粉丝 MV

把 Mili 的《world.execute(me);》做成一支**在终端里播放**的动画：
3 分 32 秒，**15 幕**，全屏铺满，**没有任何播放器框架** —— 没有顶栏、没有频谱条、
没有字幕跑马灯、没有进度条。整块终端就是画面本身，窗口多大就画多大。

一支讲「一个程序和一个人的关系」的片子。画面里始终有两个东西：大的那个是「我」，
每一幕画的主体；小的那个是「另一个」—— 一个带拖尾的亮点。两个点之间的距离就是剧情。
全片只在 13 处上屏文字，其余全部由图形承担。

> 需要一块**能显示盲文点阵（U+2800–28FF）的等宽字体**。绝大多数现代终端字体都有。
> 没有的话加 `--glyphs block`，画面会退化成实心块，仍然能看。

---

## 它是什么

- **不是**播放器，是一段动画：没有 HUD，没有时间轴，`q` 退出，`空格` 暂停。
- **自适应任何终端尺寸**：从 `20×4` 的小窗到 `200×56` 的大窗都能铺满，
  会按能力自动降级（16 色 / 256 色 / 真彩，备用屏 / 虚拟控制台，盲文 / 方块字形）。
- **跟着声音走**：画面时钟取自 mpv 的真实播放位置（IPC `time-pos`），
  不是墙上时钟 —— 卡顿或拖动之后都不会和声音失步。
- **音乐不入库**。曲子在仓库里没有，需要你自己放一份（见下）。

## 需要什么

| 依赖 | 用途 | 没有会怎样 |
|---|---|---|
| `python3` + `numpy` | 分析、渲染 | 必需 |
| `ffmpeg` | 解码音轨、首次测量 | 必需（生成分析缓存时） |
| `mpv` | 播放 + **真实播放头** | 降级成单调时钟，音画可能缓慢漂移 |
| 音轨文件 | 驱动频谱/瞬态 | **不影响运行**，自动改用 stand-in 乐谱（见下） |

## 快速开始

```sh
# 1) 把音轨放进来（文件名要一致，放仓库根目录）
#    world_execute(me)_-Mili-9893117-192.ogg

# 2) 跑
./play.sh

# 3) 想先看看结构和幕表（不播放）
./play.sh --list
```

第一次跑会花几秒把音轨做一遍 STFT 测量，结果缓存进 `mv/cache/*.npz`
（约 700 KB，已 gitignore；`--rebuild` 强制重算）。

**音轨不必叫那个名字**，也不必放在根目录：`find_track()` 会在项目里递归找
`*.ogg / *.mp3 / *.flac / *.m4a / *.wav / *.opus`，第一个命中的就是它；
也可以直接指名：

```sh
./play.sh /path/to/你的音轨.flac
```

## 音乐偏移（重要）

**这片子里所有写死的时间 —— 幕表、镜头网格、字幕时刻、故障点 —— 都是「母带时间」。**
你自己那份音轨如果前面多了一段静音、或者被裁过，整支片子就会整体错位。
`MUSIC_OFFSET` 就是用来对齐它的那**一个数字**。

```python
# mv/ttymv/player.py，文件开头「the two things you may need to change」
MUSIC_OFFSET = 0.0
```

| 你的音轨 | 设成 |
|---|---|
| 和母带一致（同一版、同一次抓轨） | `0.0` —— **不用动** |
| 前面多了静音 / 前奏更长（音乐开始得**更晚**） | **正数**，等于多了多少秒 |
| 前面被裁过（音乐开始得**更早**） | **负数** |

它同时作用于**声音**（读你文件的哪一帧）和**画面**（画片子的哪一刻），
所以改一个数字，两边一起对上。

### 怎么调

不确定差多少就**边看边调**：播放时按 `]` 加 0.1 秒、`[` 减 0.1 秒，
画面角落会短暂显示当前值（一两秒后自己消失 —— 这片子平时不放任何状态栏）。
调到你满意，**退出时会把它打印出来**，抄进 `MUSIC_OFFSET` 就固定下来了。

也可以一次性指定，不动代码：

```sh
./play.sh --offset 0.4        # 你的音轨比母带晚 0.4 秒开始
./play.sh --list              # 会打印当前偏移量
```

## 没有音乐也能跑

**音轨不存在不会报错**，会自动改用一份 **stand-in 乐谱**：从这片子**自己写死的事实**
（130.000 BPM、拍相位、15 幕的起止与响度、曲子长度）推出来的一份静音替身。

于是**写下来的东西全都照常发生** —— 每一幕、每个镜头、标题卡、字幕、进度条，
都落在原本的时间点和正确的拍子上；只有「跟着声音动」的那部分（频谱、瞬态）安静下来。
实测与真实测量渲染的逐格吻合度：boot 91%、geometry 90%、execution 83%、void 89%，
副歌 67%（那一幕几乎全部由频谱驱动，本该差最多）。

它**不会假装自己是测量结果**：`--list` 会打印 `NOT MEASURED`，
启动时 stderr 也会说明，缓存里的 `source` 字段是 `"stand-in"`。

```sh
./play.sh --no-music          # 音轨在也强制用 stand-in（调试用）
```

## 渲染成视频

同样的画面可以渲成 MP4（5760×3240 / 30fps，用的是**本机终端自己的字体** ——
读 `~/.config/kdeglobals` 里 Konsole 的配置）：

```sh
python3 mv/tools/render_video.py                 # 约 25 分钟，477 MB
python3 mv/tools/render_video.py --scale 2       # 2880×1620，快四倍
python3 mv/tools/render_video.py --bench 120     # 只测速，不编码
python3 mv/tools/render_video.py --sheet 27,150  # 只出几帧 PNG，用来核对
```

音轨在时会一起封装进去；没有音轨就出一份无声视频。
`--offset` 同样有效，会把音频从你文件里对应的位置取。

## 操作

| 键 | 作用 |
|---|---|
| `q` / `Esc` | 退出 |
| `空格` | 暂停 / 继续 |
| `←` `→` | 后退 / 前进 5 秒 |
| `r` | 回到开头 |
| `t` | 开关全部屏幕文字（只留画面） |
| `[` `]` | **音乐偏移 ∓0.1 秒**（角落里会短暂显示当前值） |

## 自检

```sh
python3 mv/tools/selftest.py     # 209 条不变量，全绿才算没坏
```

它盯的是那些**坏过一次、而且症状很难看懂**的东西：Konsole 里的重影、
纯 TTY 刷屏、标题出现两次、上屏文字必须落在官方歌词的时间戳上、
stand-in 不许冒充测量结果、音乐偏移必须真的改变画面（它曾经是死代码）、
**撕裂时间轴必须由代码内部决定**（同一时刻，测量音轨与 stand-in 撕得逐点相同）……
